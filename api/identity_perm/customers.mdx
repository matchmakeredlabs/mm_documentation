# /customers

The customers API manages MatchMaker customer accounts. A customer owns projects, defines account limits, and assigns customer-level roles to users and groups. In the MatchMaker user interface, customers are presented as organizations.

All requests require an authenticated bearer token.

## Table of Contents

| Endpoint | Description |
|----------|-------------|
| [GET - All Customers](#get---all-customers) | Retrieve the customers the caller can read. |
| [GET - Customer by ID](#get---customer-by-id) | Retrieve one customer by its ID. |
| [POST - Create Customer](#post---create-customer) | Create a managed customer account. |
| [PUT - Update Customer](#put---update-customer) | Replace an existing customer account. |
| [DELETE - Remove Customer](#delete---remove-customer) | Delete a customer account. |

## GET - All Customers

### Endpoint

```text
GET https://matchmakeredlabs.net/api/customers
```

### Notes

Returns customers on which the caller has `ReadCustomer` privilege. Global administrators and users with `ReadCustomer` on the `adminorganization` ACL scope can list all customers.

The response is an object containing an `items` array.

### Request

#### Query Parameters

Optional query parameters perform exact property matches. Multiple different parameters are combined with AND. For example:

```text
GET /api/customers?customerKind=managed&canUseApi=true
```

## GET - Customer by ID

### Endpoint

```text
GET https://matchmakeredlabs.net/api/customers/{customerId}
```

### Notes

The caller must have `ReadCustomer` privilege on the requested customer or on the `adminorganization` ACL scope.

Returns `404 Not Found` when the ID does not exist and `403 Forbidden` when the caller cannot read the customer.

None.

## POST - Create Customer

### Endpoint

```text
POST https://matchmakeredlabs.net/api/customers
```

### Notes

Creating a customer requires global administration privilege or `WriteCustomer` privilege on the `adminorganization` ACL scope. The server generates the customer UUID. Do not put an ID in the URL.

`customerKind` may be omitted and defaults to `managed`. Personal customers normally originate in self-registration. If `customerKind` is `personal`, `personalOwnerId` is required and the server ensures that the personal owner retains the `owner` role.

### Request

#### Query Parameters

None.

#### Request Body

```json
{
    "name": "ExampleOrganization",
    "description": "Example customer account",
    "roles": [
        {
            "id": "user@example.com",
            "role": "owner"
        }
    ],
    "allowedProjects": 10,
    "usersPerProject": 50,
    "elePerCollection": 5000,
    "canUseApi": true,
    "maxCollections": 100,
    "reportingCapabilities": "basic"
}
```

## PUT - Update Customer

### Endpoint

```text
PUT https://matchmakeredlabs.net/api/customers/{customerId}
```

### Notes

The caller must have `WriteCustomer` privilege on the customer or on the `adminorganization` ACL scope. PUT replaces the customer representation rather than applying a partial patch, so include all required persisted properties. The body must include an `id` that exactly matches `{customerId}`.

The read-only properties beginning with `_` may be omitted. If they are sent, the server removes them before saving.

If `roles` is omitted, the server preserves the existing role assignments. For personal customers, protected owner roles and protected account settings cannot be removed by ordinary customer members.

### Request

#### Query Parameters

None.

#### Path Parameters

| Parameter | Type | Required | Description |
|-----------|------|----------|-------------|
| `customerId` | string | Yes | Customer UUID. Must match the `id` in the request body. |

#### Request Body

```json
{
    "id": "84c45a40-c55d-4278-9a70-11432f13c1e2",
    "type": "customer",
    "customerKind": "managed",
    "name": "ExampleOrganization",
    "description": "Updated customer account",
    "roles": [
        {
            "id": "user@example.com",
            "role": "owner"
        }
    ],
    "allowedProjects": 15,
    "usersPerProject": 50,
    "elePerCollection": 5000,
    "canUseApi": true,
    "maxCollections": 100,
    "reportingCapabilities": "full"
}
```

## DELETE - Remove Customer

### Endpoint

```text
DELETE https://matchmakeredlabs.net/api/customers/{customerId}
```

### Notes

Deleting a customer requires `WriteCustomer` privilege on the customer or on the `adminorganization` ACL scope. Projects that refer to the deleted customer are not deleted or updated; their `customerId` references become orphaned.

### Request

#### Query Parameters

None.

#### Path Parameters

| Parameter | Type | Required | Description |
|-----------|------|----------|-------------|
| `customerId` | string | Yes | Customer UUID. |

## Common Status Codes

| Status | Meaning |
|--------|---------|
| `200 OK` | The operation succeeded. |
| `400 Bad Request` | The URL, body, query, or customer properties are invalid. |
| `401 Unauthorized` | Authentication is missing or invalid. |
| `403 Forbidden` | The caller lacks the required privilege. |
| `404 Not Found` | The requested customer does not exist. |
| `409 Conflict` | A record with the generated or supplied ID conflicts with an existing record. |
