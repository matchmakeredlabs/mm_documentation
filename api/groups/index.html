/groups

The groups API manages reusable sets of users and nested groups. Every group is owned by exactly one project or one customer.

All requests require an authenticated bearer token. The owner-scoped routes below are preferred because the route identifies both the owner type and owner ID:

/api/groups/{ownerType}/{ownerId}

ownerType must be projects or customers.

Owner typeStored owner propertyRead privilegeCreate, update, and delete privilege
projectsprojectReadGroup on the projectWriteGroup on the project
customerscustomerIdReadCustomer on the customerWriteCustomer on the customer

The same operations are also available through /api/projects/{projectId}/groups and /api/customers/{customerId}/groups. The unscoped /api/groups route remains available for compatibility, but requests using it must supply exactly one owner property in the body.

Table of Contents​

EndpointDescription
GET - Groups by OwnerList the groups owned by one project or customer.
GET - Group by IDRetrieve one group within its owner context.
POST - Create GroupCreate a project-owned or customer-owned group.
PUT - Update GroupUpdate an existing group's description or members.
DELETE - Remove GroupDelete a group and remove its role and group memberships.

GET - Groups by Owner​

Endpoint​

GET https://matchmakeredlabs.net/api/groups/{ownerType}/{ownerId}

Notes​

For projects, the caller needs ReadGroup on the project. For customers, the caller needs ReadCustomer on the customer. The response is an object containing an items array.

Each returned group includes ownerType and its normalized owner property (project or customerId). It also includes these computed properties:

  • _canUpdate: whether the caller may update or delete the group.
  • _groups: groups containing this group as a member.
  • _roles: project roles assigned to this group.
  • _customerRoles: customer roles assigned to this group.

Request​

Query Parameters​

Optional query parameters perform exact property matches within the selected owner. For example, ?name=Reviewers filters by group name.

Path Parameters​

ParameterTypeRequiredDescription
ownerTypestringYesprojects or customers.
ownerIdstringYesID of the project or customer that owns the groups.

Sample Request​

  • cURL
  • JavaScript
  • Python
curl \
-H "Authorization: Bearer $TOKEN" \
-X GET "https://matchmakeredlabs.net/api/groups/projects/curriculumteam"
const ownerType = "projects";
const ownerId = "curriculumteam";
const response = await fetch(
    `https://matchmakeredlabs.net/api/groups/${ownerType}/${ownerId}`,
    { headers: { Authorization: `Bearer ${TOKEN}` } }
);
const groups = await response.json();
import requests

owner_type = "projects"
owner_id = "curriculumteam"
response = requests.get(
    f"https://matchmakeredlabs.net/api/groups/{owner_type}/{owner_id}",
    headers={"Authorization": f"Bearer {token}"}
)
groups = response.json()

Sample Response​

{
    "items": [
        {
            "id": "curriculumteam:reviewers",
            "type": "group",
            "name": "Reviewers",
            "description": "Curriculum review team",
            "members": [
                "user@example.com",
                "customer-123:subjectexperts"
            ],
            "project": "curriculumteam",
            "ownerType": "project",
            "_canUpdate": true,
            "_groups": [],
            "_roles": [],
            "_customerRoles": []
        }
    ]
}

For a customer-owned group, the corresponding response contains "customerId": "customer-123" and "ownerType": "customer" instead of project.

GET - Group by ID​

Endpoint​

GET https://matchmakeredlabs.net/api/groups/{ownerType}/{ownerId}/{groupId}

Notes​

The group must belong to the owner specified in the route. A mismatched owner context is rejected even if the caller can access both owners.

Project-owned groups require ReadGroup on the project. Customer-owned groups require ReadCustomer on the customer.

Request​

Query Parameters​

None.

Path Parameters​

ParameterTypeRequiredDescription
ownerTypestringYesprojects or customers.
ownerIdstringYesOwning project or customer ID.
groupIdstringYesFull group ID in the form {ownerId}:{lowercaseName}.

Sample Request​

  • cURL
  • JavaScript
  • Python
curl \
-H "Authorization: Bearer $TOKEN" \
-X GET "https://matchmakeredlabs.net/api/groups/customers/customer-123/customer-123:subjectexperts"
const ownerId = "customer-123";
const groupId = "customer-123:subjectexperts";
const response = await fetch(
    `https://matchmakeredlabs.net/api/groups/customers/${ownerId}/${groupId}`,
    { headers: { Authorization: `Bearer ${TOKEN}` } }
);
const group = await response.json();
import requests

owner_id = "customer-123"
group_id = "customer-123:subjectexperts"
response = requests.get(
    f"https://matchmakeredlabs.net/api/groups/customers/{owner_id}/{group_id}",
    headers={"Authorization": f"Bearer {token}"}
)
group = response.json()

Sample Response​

{
    "id": "customer-123:subjectexperts",
    "type": "group",
    "name": "SubjectExperts",
    "description": "Subject-matter experts across projects",
    "members": [
        "expert@example.com"

            "role": "editor"

POST - Create Group​

Endpoint​

POST https://matchmakeredlabs.net/api/groups/{ownerType}/{ownerId}

Notes​

For a project-owned group, the caller needs WriteGroup on the project. For a customer-owned group, the caller needs WriteCustomer on the customer.

The route supplies ownership, so omit project and customerId from the request body. The server derives the group ID as {ownerId}:{lowercaseName}. A group name may contain letters, digits, and underscores, but not spaces.

members is required and contains user or group IDs. Every member must exist and must be a user or group. Nested groups are supported. Membership changes that would exceed an affected customer's permission-user limit or a project's usersPerProject limit are rejected.

Request​

Query Parameters​

None.

Path Parameters​

ParameterTypeRequiredDescription
ownerTypestringYesprojects or customers.
ownerIdstringYesProject or customer that will own the group.

Request Body​

{
    "name": "Reviewers",
    "description": "Curriculum review team",
    "members": [
        "user@example.com",
        "customer-123:subjectexperts"
    ]
}

Sample Request​

  • cURL
  • JavaScript
  • Python
curl \
-H "Authorization: Bearer $TOKEN" \
-H "Content-Type: application/json" \
-X POST "https://matchmakeredlabs.net/api/groups/projects/curriculumteam" \
--data '{
  "name": "Reviewers",
  "description": "Curriculum review team",
  "members": ["user@example.com", "customer-123:subjectexperts"]
}'
const response = await fetch(
    "https://matchmakeredlabs.net/api/groups/projects/curriculumteam",
    {
        method: "POST",
        headers: {
            Authorization: `Bearer ${TOKEN}`,
            "Content-Type": "application/json"
        },
        body: JSON.stringify({
            name: "Reviewers",
            description: "Curriculum review team",
            members: ["user@example.com", "customer-123:subjectexperts"]
        })
    }
);
const createdGroup = await response.json();
import requests

group = {
    "name": "Reviewers",
    "description": "Curriculum review team",
    "members": ["user@example.com", "customer-123:subjectexperts"]
}
response = requests.post(
    "https://matchmakeredlabs.net/api/groups/projects/curriculumteam",
    json=group,
    headers={"Authorization": f"Bearer {token}"}
)
created_group = response.json()

Sample Response​

{
    "id": "curriculumteam:reviewers",
    "type": "group",
    "name": "Reviewers",
    "description": "Curriculum review team",
    "members": [
        "user@example.com",
        "customer-123:subjectexperts"
    ],
    "project": "curriculumteam",
    "ownerType": "project",
    "_canUpdate": true,
    "_groups": [],
    "_roles": [],
    "_customerRoles": []
}

PUT - Update Group​

Endpoint​

PUT https://matchmakeredlabs.net/api/groups/{ownerType}/{ownerId}/{groupId}

Notes​

The group must belong to the owner in the route. Project-owned groups require WriteGroup on the project; customer-owned groups require WriteCustomer on the customer.

The group owner and name cannot change. PUT replaces the writable group representation, so include name, description, and the complete members array. Ownership fields and computed properties may be omitted because the route supplies ownership and the server recomputes read-only properties.

Request​

Query Parameters​

None.

Path Parameters​

ParameterTypeRequiredDescription
ownerTypestringYesprojects or customers.
ownerIdstringYesOwning project or customer ID.
groupIdstringYesFull group ID in the form {ownerId}:{lowercaseName}.

Request Body​

{
    "name": "Reviewers",
    "description": "Updated curriculum review team",
    "members": [
        "user@example.com",
        "second.reviewer@example.com"
    ]
}

Sample Request​

  • cURL
  • JavaScript
  • Python
curl \
-H "Authorization: Bearer $TOKEN" \
-H "Content-Type: application/json" \
-X PUT "https://matchmakeredlabs.net/api/groups/projects/curriculumteam/curriculumteam:reviewers" \
--data @group.json
const response = await fetch(
    "https://matchmakeredlabs.net/api/groups/projects/curriculumteam/curriculumteam:reviewers",
    {
        method: "PUT",
        headers: {
            Authorization: `Bearer ${TOKEN}`,
            "Content-Type": "application/json"
        },
        body: JSON.stringify(group)
    }
);
const updatedGroup = await response.json();
import requests

response = requests.put(
    "https://matchmakeredlabs.net/api/groups/projects/curriculumteam/curriculumteam:reviewers",
    json=group,
    headers={"Authorization": f"Bearer {token}"}
)
updated_group = response.json()

Sample Response​

{
    "id": "curriculumteam:reviewers",
    "type": "group",
    "name": "Reviewers",
    "description": "Updated curriculum review team",
    "members": [
        "user@example.com",
        "second.reviewer@example.com"
    ],
    "project": "curriculumteam",
    "ownerType": "project",
    "_canUpdate": true,
    "_groups": [],
    "_roles": [],
    "_customerRoles": []
}

DELETE - Remove Group​

Endpoint​

DELETE https://matchmakeredlabs.net/api/groups/{ownerType}/{ownerId}/{groupId}

Notes​

The group must belong to the owner specified in the route. Project-owned groups require WriteGroup on the project; customer-owned groups require WriteCustomer on the customer.

Deleting a group also removes that group from other groups and from project and customer role assignments. It does not delete the group's users or nested groups.

Request​

Query Parameters​

None.

Path Parameters​

ParameterTypeRequiredDescription
ownerTypestringYesprojects or customers.
ownerIdstringYesOwning project or customer ID.
groupIdstringYesFull group ID in the form {ownerId}:{lowercaseName}.

Sample Request​

  • cURL
  • JavaScript
  • Python
curl \
-H "Authorization: Bearer $TOKEN" \
-X DELETE "https://matchmakeredlabs.net/api/groups/customers/customer-123/customer-123:subjectexperts"
const response = await fetch(
    "https://matchmakeredlabs.net/api/groups/customers/customer-123/customer-123:subjectexperts",
    {
        method: "DELETE",
        headers: { Authorization: `Bearer ${TOKEN}` }
    }
);
const result = await response.json();
import requests

response = requests.delete(
    "https://matchmakeredlabs.net/api/groups/customers/customer-123/customer-123:subjectexperts",
    headers={"Authorization": f"Bearer {token}"}
)
result = response.json()

Sample Response​

{
    "id": "customer-123:subjectexperts"
}

Common Status Codes​

StatusMeaning
200 OKThe operation succeeded.
400 Bad RequestThe route, owner context, group ID, or request body is invalid.
401 UnauthorizedAuthentication is missing or invalid.
403 ForbiddenThe caller lacks the owner-specific privilege.
404 Not FoundThe requested group or owner does not exist.
409 ConflictA group with the derived ID already exists.
